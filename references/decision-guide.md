# 制定与检查指南

## 先看效果，再固定参数

从项目目标判断视觉取舍。销售实物的页面通常需要验证真实产品照片和规格；密集工作界面需要验证扫描效率和操作状态。例子用于帮助选择，不作为统一风格要求。

选参考时写清借鉴项：可以借排版秩序而保留自己的颜色和图片语言。参考中的自定义字体、暗色主题、圆角和卡片结构不是必选项。用户已有品牌规范时以其为准；遇到冲突说明影响。

先做能暴露问题的最小样张：代表性页面区域＋关键组件，包含桌面和手机。用长标题、真实按钮文案、最长规格和至少一种边界状态，而不是全用短英文。视觉提案如未经用户确认，标记 draft。

## 各栏目怎样决定

| 栏目 | 决定依据 | 实际检查 |
| --- | --- | --- |
| 颜色 | 品牌约束、内容层次、主操作与状态含义 | 实际文字和按钮配色的对比度，灰度下能否辨认状态 |
| 字体 | 品牌气质、阅读密度、语言覆盖、授权与加载 | 长标题换行、中文与数字混排、替代字体和手机正文 |
| 间距 | 内容亲疏与阅读顺序 | 相关资料是否聚在一起，区块是否过散或拥挤 |
| 圆角／阴影 | 品牌方向与层次用途 | 不同组件是否遵守同一逻辑，层次是否只靠阴影 |
| 布局 | 内容与关键任务 | 窄屏不挤压文字，固定元素不挡内容 |
| 组件 | 真实复用需求 | 状态完整，键盘、鼠标和触屏均可完成任务 |
| 图片 | 真实产品识别与品牌表达 | 比例、裁切焦点、分辨率、缺图、图文对应 |
| 动效 | 操作反馈、状态变化或必要说明 | 快速重复操作、减少动态效果设置、低性能设备 |

数值必须来自批准规范、已检查的设计或明确标注的提案。初始提案可用少量间距级别与字体层级；根据实际内容增加，避免为了填满模板创造不用的级别。

## 结构和引用

YAML 使用具体值或完整对象。{colors.primary} 表示引用 colors 下的 primary；{typography.button} 表示引用整个字体对象。每个引用都必须有目标。避免循环引用。手机覆盖写出适用条件和具体变化，不能只写“自适应”。

草案的未知值记录到 Open Questions；参数只填具体值或有效引用。approved 范围内不能依赖未解决设计值。文档中的数值与代码、Figma 变量不一致时，记录哪个是权威来源；未经授权不自动重写现有实现。

## 检查与证据

- 采用项目既定可访问性目标；没有时以 WCAG 2.2 AA 为检查基线。运行时使用当前官方资料：https://www.w3.org/TR/WCAG22/ 。分别检查适用条款；单项对比度通过不等于整体合规。
- 正常文字通常需 4.5:1；符合大字条件的文字通常需 3:1；适用的非文字界面元素需 3:1。记录实际颜色组合与计算结果，不能凭眼判断。
- 操作目标按适用条款检查尺寸、间距及例外；常用触屏主操作可设计得更大。键盘焦点应可见，固定导航不应遮住焦点。
- 使用项目真实断点并检查至少一个窄手机和桌面尺寸；记录具体宽高。检查缩放、长文案、空内容和错误状态（适用时）。
- 动画只为可解释的目的存在。常规反馈保持迅速；减少动态效果时保留理解状态所需的信息。触屏不依赖 hover。
- 浏览器截图、Figma 画面或渲染产物必须实际打开检查。无法访问字体、设备或工具时保留“未验证”，不要声称实测。

## 交付边界

供真人 designer：按模板出规则和可见样张，记录决定理由与状态。供 AI designer：读取 SKILL.md 执行流程，产出同样的资料。文件结构可复用，品牌参数不跨项目自动继承。交付文档后，后续实施仍需核对映射和实际页面。
